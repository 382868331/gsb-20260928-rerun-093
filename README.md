# 本地消息投递运行系统

这是一个只依赖 Go 标准库的本地持久消息 Broker，不接入任何外部中间件。当前阶段建立主题、订阅、消费位置与确认语义，路由能力保留为后续阶段扩展。

## 投递语义

- 主题用 `CreateTopic` 建立；订阅用 `Subscribe` 建立，可从最早消息或指定偏移开始。
- 消息与订阅状态在每次发布、领取、确认、超时转交后原子写入本地 `broker.json`。
- 同一条消息在同一订阅上同一时刻只能被一个消费者持有。
- 未确认租约超时后重新变为可投递状态，再次领取会生成新的 attempt 和不可猜测的 token。
- 确认必须同时匹配消息序号、消费者 ID 和当前 token；超时转交后的旧确认不会影响新持有人。
- 普通重启后，已确认消息保持 `acked`；未确认租约视为处理中断，会重新投递，attempt 加一。
- 每条消息保存完整投递轨迹，可通过 `Snapshot` 核对实际消费者、尝试次数和最终状态。

## 测试端

运行内置场景：

```bash
go run ./cmd/testclient -data /tmp/message-delivery-data
```

该端会发布一条消息，先交给 `consumer-a`，等待租约超时后转交给 `consumer-b`，再验证 A 的旧确认失败、B 的新确认成功。
