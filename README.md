# 消息投递运行系统（第一阶段）

本地持久化消息投递：主题、订阅、消费位置、独占投递与确认，支持延迟投递、失败退避、多次失败隔离与人工重新投递。生产与消费均由项目内测试端（broker/ 下 *_test.go）完成，不接中间件。路由能力留待后续阶段。

## 结构

- broker/broker.go — 主题/订阅/消费位置、Pull/Ack、超时回收与纪元 fencing
- broker/store.go — 磁盘持久化与重启恢复
- broker/broker_test.go — 测试端（生产者 + 多消费者场景）

## 持久化布局

- topics/<topic>.jsonl — 消息日志（追加写 + fsync）
- subs.json — 订阅与已确认偏移（临时文件 + rename 原子重写）
- acks.jsonl — 每条消息的实际去向记录（谁、何时、以何纪元确认）
- history.jsonl — 消息历史：每次领取、超时回收、拒绝、确认、隔离与人工重投各一条记录

## 语义

- 每条消息同一时刻只有一个当前持有人（可见期内其他消费者拉不到）。
- 超时未确认即回收转交，纪元递增；旧持有人的 Token 立即失效（ErrStaleToken），不会误伤新持有人。
- PublishDelayed 支持延迟投递，可见时间之前任何消费者都拉不到。
- Nack 显式拒绝并进入退避期，退避结束后可重新投递；累计失败（拒绝或超时）达到 MaxAttempts 后消息被隔离。
- 隔离不阻塞同订阅后续可处理消息；连续消费位置（Position）只统计已确认前缀，跳过失败消息不会误认前序已完成。
- Redeliver 人工重投已隔离消息：保留原偏移身份，开启新一轮尝试，操作人记入历史。
- History 返回每条消息的完整尝试记录；最终确认者（AckedBy）只是其中一条 ack，不代替全部尝试。
- 确认写盘后才算完成；普通重启后已确认消息不会重来，未确认消息允许重新投递。
- 重启后可用 AckedBy 核对每条消息的实际去向。
